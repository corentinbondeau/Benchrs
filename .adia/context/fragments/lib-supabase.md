## Responsibility
Supabase client factories for browser, server, and admin contexts.

## Key Files
| File | Role |
|------|------|
| client.ts | Browser client (singleton via `createBrowserClient`) + `getSessionAccessToken` |
| server.ts | Server client (cookie-based, for server components/actions) |
| admin.ts | Admin client (service role key, bypasses RLS) |

## Patterns
- Browser: `@supabase/ssr` `createBrowserClient()` returns SINGLETON
- Channel names must include `useId()` suffix to avoid realtime conflicts
- Server client: reads cookies from `next/headers` — used in server components
- Admin client: uses `SUPABASE_SERVICE_ROLE_KEY` — API routes only

## Performance Notes
- Singleton pattern is correct — no duplicate clients
- Server client is NOT used by any page (all pages are `"use client"`)
- Migration to Server Components would leverage `server.ts` for data fetching
