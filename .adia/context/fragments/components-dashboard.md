## Patterns
- All use `useQueryCache(key, fetcher)` — deduplicates concurrent calls, 30s TTL
- Each widget creates its own `createClient()` (singleton, so OK) and calls `.from()`
- Dashboard home loads widgets by role: Coach (7 widgets), Player (1), Parent (1)
- `NewsFeed` and `SeasonSummary` use `next/dynamic` (code-split)
- `CoachWeekOverview`, `PendingConvocations`, `ParentDashboard` use `LazyMount` (visibility-based)

## Performance Issues (CRITICAL)
- **Waterfall**: Each widget fires its own Supabase query on mount — no batching, no parallel Promise.all
- **CoachWeekOverview**: 6 sequential `.from()` calls inside one `useQueryCache` fetcher
- **PendingConvocations**: 3+ queries (attendances + profiles + parent_student)
- **ParentDashboard**: complex multi-child query chain
- **No server-side data fetching**: all data arrives AFTER JS loads + hydrates + mounts + queries Supabase
- **No loading skeletons on individual data fields** — whole card flashes from skeleton to content
