## Responsibility
In-memory query cache with TTL, request deduplication, and pub/sub for cross-component sync.

## Architecture
- **Map-based cache**: `key → { data, expiresAt }` — lives in module scope (shared across components)
- **In-flight deduplication**: `inFlight Map` prevents duplicate fetches for same key
- **Pub/sub**: `subscribers Map` notifies all hooks watching the same key when data updates
- **TTL**: 30 seconds default, configurable per call

## API
- `useQueryCache<T>(key, fetcher, { ttl? })` — React hook, returns `{ data, loading, revalidate }`
- `getQueryCache<T>(key)` — sync read from cache
- `setQueryCache<T>(key, data, ttl)` — sync write + notify subscribers
- `clearQueryCache(key?)` — invalidate one or all

## Performance Characteristics
- **Pros**: deduplicates concurrent requests, 30s TTL reduces refetches, pub/sub updates all watchers
- **Cons**: 
  - Lost on page navigation (in-memory only, no persistence)
  - No stale-while-revalidate pattern
  - No background refresh
  - No error caching (failed fetches retry immediately)
  - 30s TTL is aggressive for data that changes rarely (team info, profiles)
