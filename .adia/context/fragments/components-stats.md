## Edition inline des attributs joueur (2026-08-27, fiche-joueur-composition)
`PlayerProfile.tsx` permet desormais a un **coach** d'editer directement, depuis la fiche joueur, le **pied fort**, le **poste principal** et les **postes secondaires**.

- Etats locaux : `editingAttributes`, `preferredFootInput`, `positionInput`, `secondaryPositionsInput`
- Handler : `handleSaveAttributes()`
- Imports : `POSITIONS` depuis `@/lib/positions` (re-export de `@/lib/lineup/positions`) et `buildProfileAttributesPayload` depuis `@/lib/profile/buildProfileAttributesPayload`
- Le payload d'`update` sur `profiles` est **toujours** construit par `buildProfileAttributesPayload` (normalisation + dedoublonnage + exclusion du poste principal des secondaires)
- ⛔ Ne jamais inclure la cle `role` dans l'update : trigger SQL `prevent_self_role_change` (`072_security_fixes.sql:49-66`)
- Ces attributs alimentent directement `autoCompose` (`lib/lineup/autoCompose.ts`) : un poste mal saisi degrade la composition automatique. `preferred_foot`, lui, n'influence **jamais** la composition.

## REGLE METIER — Assiduite (2026-08-25)
> **L'assiduite ne compte QUE la presence aux ENTRAINEMENTS** (`events.type='training'`), jamais les matchs. "present" = status `present|late`. Helper central : `computeAttendanceRate(attendances, eventIds)` dans `src/lib/attendance/` (voir fragment lib-attendance.md).

- **PersonalGoalsCard.tsx** : objectif "assiduite" via `computeAttendanceRate` sur les trainingIds ; les `match_stats` restent sur les matchs.
- **PlayerBadgesCard.tsx** : `attendanceRate` (badge "Assidu") + `bestStreak` calcules sur les entrainements uniquement.
- **CoachStats.tsx** : breakdown "Assiduite par evenement" (type affiche par ligne) — **HORS PERIMETRE**, laisse volontairement inchange.
- Deja corrects (filtraient deja training) : PlayerProfile, PlayerPaniniCard, Leaderboard.
