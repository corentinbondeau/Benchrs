# Security
> Generated by @init_project on 2026-08-18 — Project benchrs
> Last update: 2026-08-18

## Authentication
- Supabase Auth (email/password, JWT)
- Session cookie: `sb-*-auth-token`
- Middleware: `src/proxy.ts` — redirects unauthenticated users, protects routes

## API Security
- `getAuthUser` + `isTeamMember` / `isTeamCoach` guards on all API routes
- `authFetch` client helper adds Bearer token
- `createAdminClient` for server-side operations (requires `SUPABASE_SERVICE_ROLE_KEY`)
- Anti-enumeration on forgot-password

## Headers (next.config.ts)
- `Strict-Transport-Security` (HSTS 2 years + preload)
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Content-Security-Policy` (restrictive, allows Supabase + Open-Meteo + Nominatim)
- `Permissions-Policy` (geolocation/microphone/payment denied, camera allowed for uploads)

## Data Protection
- RLS on all tables via SECURITY DEFINER functions
- Storage paths scoped per user/team
- SSRF protection on FFF proxy

## Potential Issues
- VAPID keys have hardcoded fallback (not ideal for production rotation)
- `SUPABASE_SERVICE_ROLE_KEY` was placeholder on Vercel (documented gotcha)
