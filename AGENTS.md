# Sportplus — Agent Memory

## Objective
Build a mobile-first football team management app (Sportplus) with Supabase backend.

## Important Details
- **Déploiement (pré-prod puis pro)** : la branche de production Vercel est `production` (plus `main`). Un push sur `main` (ou une PR) crée UNIQUEMENT une préview/pré-production (`vercel inspect <url>` → `githubCommitSha`). MISE EN PRO = merge vers `production` : `git push origin main:production` → déploiement prod automatique (build frais avec envs de prod). Le user valide TOUJOURS une préview avant mise en pro ; NE JAMAIS déployer en prod sans validation. `MISTRAL_API_KEY` est dispo en preview ET prod.
- Génération de séances IA (`/api/trainings/generate`) : Mistral (clé `MISTRAL_API_KEY`, pas de SDK, `fetch` direct), 4 sections, somme des durées = 90 min (validation + 1 retry), PDF via `@react-pdf/renderer`. **Gotcha mobile** : ne PAS afficher le PDF via une URL `data:application/pdf` dans un `<iframe>` (invisible sur iOS/Android) → convertir le base64 en `Blob` + `URL.createObjectURL` dans la page `trainings/generate/page.tsx`.
- Prompt IA (`src/lib/training/ai-generator.ts`) : persona entraîneur + préparateur physique, expert en prépa physique/athlétisation, animation offensive, animation défensive et systèmes de jeu (`FOOTBALL_SYSTEMS` = 4-3-3, 4-2-3-1, 4-4-2, 3-5-2, 5-3-2). Sélecteur « Système de jeu (optionnel) » sur la page (body `systeme`). **Niveau d'expertise IA** (`EXPERTISE_LEVELS` = BMF / BE / UEFA B / UEFA A, default UEFA B) : persona adapté par niveau (`buildBasePersona(expertise)`, `buildSystemPrompt(phase, expertise)`), sélecteur sur les 3 appels (`trainings/generate`, tactics Séance, `SessionFiche`), body `expertise` validé dans `/api/trainings/generate`. **Animation simple** : champ `animation` (déroulé numéroté 1..6 en langage clair) dans chaque `FicheSection`, demandé dans le prompt, parsé avec fallback `""`, rendu en vert (PDF `SectionBlock` + `AIFicheView` + page generate) — alternative simple au schéma. Phase `ATHLETISATION` = phase récurrente APRÈS la préparation physique de reprise (2-3 semaines) : maintien/développement des qualités physiques, intensité modérée adaptée au calendrier ; structure dédiée (Échauffement/Mobilité → Aérobie/Endurance → Renforcement/Circuit → Retour au calme) ; objectifs dans `src/lib/training/phases.ts`.
- **Compte-rendu de match IA** : table `match_reports` (event_id UNIQUE, team_id, content JSONB, migration `037_match_reports.sql` à appliquer ; RLS membres SELECT + coachs manage via `public.is_team_coach`). Route `/api/matches/report` (GET = lecture, POST = génération coach-only via Mistral `fetch` direct → rapport {title, summary, points_forts[], points_faibles[], axes_progression[], note_equipe, meilleurs_joueurs[{nom,raison}]}, upsert). UI `src/components/match/MatchReportCard.tsx` sur `matches/[id]` : bouton « Générer le rapport IA » (désactivé tant que le score n'est pas renseigné), à chaque génération → notification type `match_report` aux joueurs actifs + leurs parents (url `/matches/[id]`).
- **Retour du coach (feedback match)** : `src/components/match/MatchFeedback.tsx` sur `matches/[id]` — notes 1-10 + commentaire par joueur via `match_ratings` (upsert, rater = coach, `team_id` dispo sur la table), à l'enregistrement → notification type `match_retour` à chaque joueur concerné + ses parents (url `/stats/[playerId]`).
- **Alertes VMA/VMI** : helper `src/lib/playerAlerts.ts` (`notifyPhysicalTest`) appelé après succès des RPC dans `physical/tests/page.tsx` (par joueur) et `PlayerProfile.tsx` (skip si le coach modifie SA propre fiche) → notification type `physical` au joueur + ses parents.
